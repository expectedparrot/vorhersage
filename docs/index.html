Vorhersage
German for “forecast.”

01 / The workbench

A process an agent can resume.

The agent researches the world and supplies judgments. Vorhersage stores the state, supplies the next task, validates its inputs, performs declared calculations, and preserves the resulting forecast.

01

Define the event

Fix YES, NO, and void rules, a deadline, and a resolution source before interpreting the probability.

02

Trace the evidence

Keep sourced findings, copied reports, contradictions, and explicit unknowns attached to the reasoning.

03

Preserve the forecast

Freeze the estimate and its inputs. Record revisions as new forecasts, with links to their predecessors.

04

Learn from outcomes

Resolve the precise question, compare eligible forecasts, and inspect Brier scores and descriptive calibration.

A clear boundary. The CLI does not choose a model or web service. Agents and configured workers collect evidence and interpret it. A complete workflow establishes an audit trail; forecasting accuracy still needs evaluation.

02 / Get started

Run a complete example offline.

Install from the repository in a Python 3.11+ environment. The core package needs no API keys or additional runtime libraries.

Terminal / install
git clone https://github.com/expectedparrot/vorhersage.git
cd vorhersage
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
vorhersage version

The fictional factory walkthrough uses separate CLI processes to create questions, issue forecasts, revise them, resolve outcomes, and calculate matched scores.

Terminal / offline walkthrough
python examples/factory/walkthrough.py /tmp/vorhersage-demo
vorhersage --project /tmp/vorhersage-demo status
vorhersage --project /tmp/vorhersage-demo doctor

Use a new destination directory for each walkthrough. Its fictional probabilities and scores demonstrate software behavior, not forecasting skill.

Start your own project

Global --project goes before the command. Inspect each schema, then author the corresponding JSON file.

vorhersage init ./my-study --name "My forecast study"
vorhersage schema question
vorhersage --project ./my-study question add --from question.json
vorhersage schema run
vorhersage --project ./my-study run start --from run.json

Use kind: "real" and mode: "prospective" for a live event. All timestamps need a timezone. Record whether research has already started with research_status.

03 / The operating loop

One explicit step at a time.

  1. PriorLabel the starting judgment or reference class.
  2. DriversDescribe paths to YES and NO.
  3. ResearchCover each required domain; explain unknowns.
  4. AssessmentSupply a judgment or a declared calculation.
  5. ReviewChallenge the estimate in both directions.
  6. IssueFreeze the forecast and set review triggers.
Terminal / resume and submit
vorhersage --project ./my-study next --run RUN_ID
vorhersage --project ./my-study submit --run RUN_ID --from result.json

next is read-only. It returns the task, payload schema, budget, context, and exact revision. The agent supplies the requested payload; submit accepts it atomically. Identical retries are idempotent, and stale revisions are rejected.

What an agent submits
{
  "task_id": "task_FROM_NEXT",
  "expected_revision": 0,
  "idempotency_key": "my-unique-submission",
  "payload": {
    "method": "judgment",
    "probability": 0.3,
    "rationale": "An explicitly subjective starting estimate.",
    "limitations": ["No adequate reference class yet."],
    "evidence_refs": []
  }
}

This is an illustrative prior response. Replace task IDs and revisions with the values returned by next. Subsequent tasks have different payload schemas.

Keep prior timing honest. Set research_status to not_started, in_progress, or completed when opening a run. Research done before registration does not become a pre-research prior merely because a task is named “prior.”

04 / Research you can inspect

Keep claims connected to their sources.

Use Epiq as the shared factual store, then freeze selected answers into portable evidence packets. Or import source-linked findings from any research provider using a research bundle.

Terminal / capture and audit
vorhersage schema research_bundle
vorhersage --project ./my-study research capture --from bundle.json
vorhersage --project ./my-study packet audit PACKET_ID

vorhersage --project ./my-study epiq freeze \
  --db /path/to/research.sqlite --from selection.json
What the evidence record preserves
FieldPurpose
Claim typeSeparate reporting, official statements, observations, and inferences.
Publication & retrieval timesDistinguish when information appeared from when it was collected.
Capture & supporting textVerify supplied content hashes and quoted excerpt membership.
Source relationshipsRecord repetitions, declared independent confirmations, and contradictions.
Evidence referencesConnect the source record to the tasks and forecasts that used it.

Audits flag provenance gaps and conflicting claims of source independence. Distinct source groups are not automatically independent, and source counts are not probability multipliers.

05 / An optional calculation

See which assumptions move the answer.

A scenario mixture combines mutually exclusive possibilities. The agent defines the scenarios and their probabilities; the tool checks the weights and computes the result. No domain-specific model is required.

Try it / fictional example
Overall success probability52%

0.60 × 0.80 + 0.40 × 0.10 = 0.52

Green: contribution from ready. Gold: contribution from not ready. The remaining space is failure probability.

The complementary scenario always receives the remaining weight. These inputs are illustrative judgments, not measured frequencies. The CLI also calculates sensitivity bounds when ranges are supplied.

Terminal / calculate without issuing a forecast
vorhersage scenario --from examples/workbench_extensions/mixture.json

To use the calculation in a workflow, choose method: "scenario_mixture" for the assessment. Simple judgments, nested conditional paths, and explicit ensembles remain available. Read the assumptions and sensitivity rules →

06 / After issuance

A forecast is a record you revisit.

Each issued forecast has a review time and observable update triggers. A revision starts a new run linked by previous_forecast_id, preserving the original estimate and its evidence.

Terminal / review queue and polling
vorhersage --project ./my-study monitor
vorhersage schema watch
vorhersage --project ./my-study watch add --from watch.json
vorhersage --project ./my-study watch tick
vorhersage --project ./my-study watch run --interval 30

monitor lists due work without changing state. A configured watch can check Epiq or collect fresh evidence through a research worker, register changes, and start or resume a revision. An optional agent worker supplies validated responses through review and issuance.

Workers receive JSON on stdin and return JSON on stdout. Failed calls are recorded for retry. A fresh retrieval timestamp alone is not a new finding. After a deadline, due work goes to resolution research; the tool never infers a NO outcome from silence alone.

Running the loop. watch run polls while the process runs; watch tick fits an external scheduler. Configure your workers first. No OS service is installed automatically. Polling currently requires macOS or Linux.

07 / Check the forecast

Compare like with like.

Resolve the exact question version with outcome evidence. Evaluation selects eligible forecasts at a stated cutoff, computes Brier scores, and reports matched comparisons, missingness, and descriptive calibration bins. Prospective, retrospective, and simulation forecasts are kept separate.

Build reference classes

Store historical episodes with reference add. Query a chosen horizon and knowledge cutoff. Cases observed too briefly are reported as censored.

Check related events

Register version-specific implications with relation. coherence checks probability ordering, including transitive relationships.

Historical replay can be contaminated by a model’s knowledge of the outcome. The included model pilot documents that limitation. Completing a structured process is useful evidence of software behavior; it does not establish superior predictive accuracy.

08 / Command reference

JSON in. Reviewable records out.

Use vorhersage guide, vorhersage schema NAME, and command-level --help to discover the interface. Ordinary output is a JSON envelope; errors go to stderr with a nonzero exit code. --from - accepts stdin.
